# Abuashia Michael Jinks — Portfolio

A single-page portfolio built with plain HTML, vanilla JavaScript, and Tailwind CSS v4 (CLI-only, no `tailwind.config.js`). Styled around a glassmorphic, iOS-style visual language: one dark base, one light/glass tone, one accent — with a floating "dynamic island" nav and Apple-style motion (scroll reveals, hero parallax, all reduced-motion aware).

## Project structure

```
.
├── index.html          Page markup, all Tailwind utility classes
├── src/
│   └── input.css        Tailwind v4 entry point — theme tokens (@theme), keyframes
├── js/
│   └── app.js            Vanilla JS: mobile menu, scroll reveal, nav-on-scroll, hero glow
├── assets/               Put resume.pdf and any real project screenshots here
├── dist/                 Generated by the build — NOT included, see below
└── package.json
```

## Why there's no `dist/output.css` yet

This repo ships **unbuilt** on purpose — `dist/output.css` is generated from `src/input.css` by the Tailwind CLI scanning `index.html` for the utility classes it actually uses. Run the build once before deploying (or let your host run it for you) and the file will appear.

## Setup

```bash
npm install
```

## Build

One-off production build (minified):

```bash
npm run build
```

Rebuild automatically while you edit:

```bash
npm run watch
```

Either command outputs `dist/output.css`, which `index.html` already links to.

## Deploying

- **Netlify / Vercel:** set the build command to `npm run build` and the publish/output directory to the project root (the site reads `./dist/output.css` relatively, so no path changes needed).
- **GitHub Pages:** GitHub Pages doesn't run a build step for you. Run `npm run build` locally first, then commit the generated `dist/output.css` (or add a small GitHub Actions workflow that runs `npm run build` and pushes `dist/` before Pages deploys).

## Customizing the theme

All design tokens live in `src/input.css` under `@theme` — colors, font stack, and animation keyframes. Because this is Tailwind v4, changing a value there (e.g. `--color-signal`) automatically updates every `bg-signal`, `text-signal`, `border-signal/20`, etc. utility across the whole site — no config file to touch.
