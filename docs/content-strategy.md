# Content Strategy

> Version 1.0
> Last Updated: July 2026

---

# Purpose

The Portfolio Blog exists to document my journey as I transition from Mechanical Engineering into Full-Stack Development and Artificial Intelligence Engineering.

Rather than only showcasing completed projects, the blog serves as a public record of continuous learning, experimentation, problem-solving, and product development.

Every article should provide practical value while demonstrating my growth as an engineer.

---

# Mission Statement

Learn in Public.

Build in Public.

Share Everything.

The objective is not merely to display finished work, but to openly document the engineering process—from first ideas and early prototypes to production-ready systems.

---

# Vision

Create a high-quality technical publication that showcases:

- engineering thinking
- software craftsmanship

The long-term goal is to establish the portfolio as a trusted resource for developers while serving as a living record of my career.

# Writing Style

Tone should be:

- professional
- approachable
- practical
- honest
- concise

Write as if explaining concepts to another developer.

Avoid unnecessary jargon.

Prefer examples over theory.

---

# Voice

The writing voice should reflect:

- curiosity
- humility
- confidence without exaggeration
- continuous learning

The goal is to educate rather than impress.

---

# Article Structure

Recommended structure:

```
Title

↓

Introduction

↓

Problem

↓

Solution

↓

Implementation

↓

Lessons Learned

↓

Conclusion

↓

Next Steps
```

Readers should understand both **what** was built and **why** certain decisions were made.

---

# Publishing Frequency

Recommended cadence:

- One technical article each week.
- One "Building in Public" update every one to two weeks.
- One in-depth project case study after major releases.

Quality should always take priority over quantity.

---

# SEO Guidelines

## Titles

Use descriptive titles.

Good

```
Building an AI Chatbot with Golang and OpenAI
```

Avoid

```
My New Project
```

---

## URLs

Use lowercase.

Separate words with hyphens.

Example

```
building-ai-with-golang
```

---

## Excerpts

Length:

120–180 characters.

Summarize the value of the article rather than repeating the title.

---

## Headings

Use a clear hierarchy.

```
H1

↓

H2

↓

H3
```

Avoid skipping heading levels.

---

## Internal Links

Whenever appropriate, link to:

- related articles
- project pages
- GitHub repositories
- portfolio sections

This helps readers discover more of the site.

---

# Images

Every article should include:

- Featured image
- At least one relevant diagram, screenshot, or illustration where it improves understanding

Guidelines:

- Use descriptive filenames.
- Compress images.
- Provide meaningful alt text.

---

# Code Examples

All code should:

- compile or run as shown (where applicable)
- be tested before publishing
- focus on the concept being explained
- include syntax highlighting

---

# Cross-Posting Strategy

After publishing a new article:

## LinkedIn

Share:

- a concise summary
- key takeaway
- link to the article

---

## GitHub

If the article references code:

- push the repository
- tag the release when appropriate
- reference the repository in the article

---

## YouTube

When appropriate:

- record a companion walkthrough
- link back to the article
- include the repository in the description

---

## X (Twitter)

Share:

- one key insight
- one code snippet
- one image
- article link
